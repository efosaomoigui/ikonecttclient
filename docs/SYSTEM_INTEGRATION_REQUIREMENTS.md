# IKONECTT — SYSTEM INTEGRATION REQUIREMENTS

Please use this questionnaire to confirm which systems own each record and how Ikonectt should connect to them. For every API we agree to use, please provide sandbox access, sample records, API documentation with request and response examples, and a technical contact. Include the authentication method and scopes, credential rotation, network restrictions, limits, error meanings, and any production differences. For events, include signatures, stable event IDs, delivery retries, ordering and replay rules. If an operation is unavailable, please describe the approved manual alternative.

| --- | --- | --- | --- | --- |
| Customer / CRM | Link staff-created profiles to the correct customer, using a stable customer ID, account number, contact details and status. | Lookup by a stable ID. Confirm whether create or update must be sent to your CRM. Return the canonical ID, version and status, or a duplicate, not-found or conflict response. | Customer updates, merges or deactivation, if your CRM owns those records. A periodic lookup can substitute where appropriate. | Local profile and external references exist. Confirm ownership and mapping before sharing customer data. External CRM sync depends on that decision. |

An external identity API is required only if you own authentication. Confirm the approved recovery delivery channel. |

Additional SMS and marketing channels are optional. |

## Decisions needed first

1. Who owns customer identity, plan prices, subscription status, coverage, wallet funds and support tickets?
2. Can you supply mapped sandbox customers, addresses, wallets and subscriptions, including pending and failed cases?
3. Which payment and provisioning steps can the client confirm electronically? Who handles a confirmed debit with activation still pending?
4. Which sender and channel are approved for recovery messages? Who owns delivery monitoring?
5. Who can approve the field mapping, sandbox evidence and production cutover?

Signed event delivery is optional when authoritative status checks are available and meet the agreed freshness and recovery requirements. External CRM, identity and ticketing APIs are conditional on the ownership decisions above. AI-assisted support is a separate approval and is outside these launch API dependencies.
