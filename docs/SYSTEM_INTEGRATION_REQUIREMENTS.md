# IKONECTT — SYSTEM INTEGRATION REQUIREMENTS

Please use this questionnaire to confirm which systems own each record and how Ikonectt should connect to them. For every API we agree to use, please provide sandbox access, sample records, API documentation with request and response examples, and a technical contact. Include the authentication method and scopes, credential rotation, network restrictions, limits, error meanings, and any production differences. For events, include signatures, stable event IDs, delivery retries, ordering and replay rules. If an operation is unavailable, please describe the approved manual alternative.

## Decisions needed first

1. Which account identifier and ownership proof should we use to link customers, and which client systems own plan prices, subscription status, coverage, wallet funds and support tickets?
2. Can you supply mapped sandbox customers, addresses, wallets and subscriptions, including pending and failed cases?
3. Which payment and provisioning steps can the client confirm electronically? Who handles a confirmed debit with activation still pending?
4. Which sender and channel are approved for recovery messages? Who owns delivery monitoring?
5. Who can approve the field mapping, sandbox evidence and production cutover?

Signed event delivery is optional when authoritative status checks are available and meet the agreed freshness and recovery requirements. Customer verification and profile retrieval are required. Ticketing integration is conditional on ownership. AI-assisted support is a separate approval and is outside these launch API dependencies.
